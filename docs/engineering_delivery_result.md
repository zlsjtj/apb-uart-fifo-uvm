# 本轮工程优化结果

## 做了什么

本轮没有继续改 UART 功能，保留前几轮已经实现的 APB、CDC、TX_BUSY、RAL 和无探针验证成果，重点处理运行与交付。

1. 工具配置集中到 config/toolchain.psd1，机器路径可放在不提交的 toolchain.local.psd1 或环境变量中。完整验收先检查实际工具版本、器件支持和仿真启动，结果写入 runtime_manifest.json。
2. 交付包按 runId 从通过的独立快照生成。源码、说明、日志、UCDB 和 HTML 都进入相对路径校验清单。校验完成后才更新 reports/published/latest.json，历史包不覆盖。
3. 新增 expanded 种子模式。两轮压力测试和 mutation 分别使用 campaign seed 10000、20000；每个故障仍与同测试、同种子的正确基线成对运行。
4. 收拢当前架构入口，补三张可编辑架构图、复现说明及 TX 完成案例。论文结果表由实际报告生成，不再手工拼接不同轮次的数字。

## 交付流程另做了什么检查

第一份真实交付包含 3,876 个文件，约 26.2 MB。完整复制到另一个目录后仍可校验；修改副本 README 后会被哈希检查拒绝。运行中的验收不能发布，重复导出不能覆盖正式包，这两种失败均没有改变最新发布入口。记录在 reports/delivery_integration_tests.json。

正向搬移测试后的副本被故意改坏，用于反向测试，留在被 Git 忽略的 relocation_check 目录；它不是正式交付包。正式包只认 reports/published/latest.json 指向的目录。

两个运行的完整目录、发布摘要和清单均保留。论文结果表中的 10 个相对证据链接在第一份完整包和轻量发布目录中分别检查通过；最终包发布时再次进行文件完整性校验。源码哈希不包含文档，交付清单另行覆盖每轮快照中的文档；这份仓库总结在两轮结束后写入，不冒充快照内的测试输入。

## 使用边界与后续

当前结论仍是简化 8N1 模型的仿真、覆盖率闭环和 OOC 综合，不是无缺陷证明、商业 CDC/RDC 签核、布局布线或板级串口实测。真实异步 RX 没有在本轮扩展。

下一步适合按学院格式写论文正文、整理演示和答辩，不必再围绕现有 RTL 做大拆分。上板如有要求，应单独制定异步 RX 与板级验收计划。

本轮按用户授权提交并推送。提交号以 Git 历史为准，执行源码以以上 SHA-256 为准，两者不是同一个概念；提交前核对暂存区内容，推送后核对 origin/main。
