# 项目范围与验收说明

## 1. 项目定位

**暂定题目：** 基于 UVM 的 APB-UART 异步 FIFO 验证平台设计与覆盖率闭环

本项目的重点是验证，不是把 UART 做成可直接商用的完整 IP。DUT 采用一个带 APB 寄存器接口、TX/RX 异步 FIFO 和简化串行收发逻辑的 UART 模型；围绕它搭建 SystemVerilog/UVM 验证环境，完成从测试激励、结果检查、断言、覆盖率到回归报告的验证闭环。

这样定位有两个好处：一是现有 RTL 和 UVM 环境能够自然衔接；二是后续工作可以集中在“验证是否充分、证据是否可信”上，而不是无止境地扩展 UART 功能。论文中不把“使用 UVM”本身当成创新点，重点说明平台如何发现问题、如何度量验证完成度，以及异步 FIFO 和跨时钟场景如何被验证。

## 2. 当前基础

仓库已经具备以下内容：

- APB 从设备寄存器接口，包含 `CTRL`、`STATUS`、`BAUD`、`TXDATA` 和 `RXDATA`；
- UART TX/RX、回环路径和 TX/RX 异步 FIFO；
- APB agent、UART agent、scoreboard、functional coverage、SVA 和基础回归脚本；
- 寄存器访问、loopback、IRQ、外部 RX、TX FIFO 满、非法访问、随机数据和 disable/enable 恢复等基础用例；
- 15 个用例、三组基准 seed 的 Questa 正式回归记录；
- 一套轻量 UVM RAL，包含 APB adapter、被动 predictor 和复位镜像检查。
- 独立 RX 引脚监视器、参考预测器，以及 UART 域配置生效事件监测。
- 统一环境配置、virtual sequencer、按功能拆分的 sequence/test 文件和一键验收入口。

这些内容说明项目不是从零开始，也不能把“45/45 PASS”单独当成验证结束。目前已形成覆盖率合并报告，通过 TX 数据、IRQ 控制和 FIFO full 控制三类故障注入验证了检查器的有效性，完成 45 次多 seed 正式回归，并完成 CDC 结构审计、复位同步释放、寄存器模型统一以及 predictor/scoreboard 职责拆分；剩余工作主要是商业 CDC/lint 条件下的补充检查和论文、答辩材料整理。

## 3. 本阶段要解决的问题

本阶段要回答的不是“UART 能不能发一个字节”，而是下面四个问题：

1. APB 寄存器访问、串行收发和异步 FIFO 的关键功能是否按规格工作；
2. 在 FIFO 满/空、错误访问、帧错误、复位和时钟域切换等边界条件下，DUT 是否保持可预期的行为；
3. UVM 环境能否独立发现数据、状态和时序上的错误，而不只是让测试流程走完；
4. 是否能够用回归和覆盖率数据说明验证工作已经达到预定范围。

## 4. 功能范围

### 4.1 DUT 范围

本项目验证的 DUT 包含：

- 零等待状态的 APB 从设备接口；
- `CTRL`、`STATUS`、`BAUD`、`TXDATA`、`RXDATA` 五组寄存器；
- 1 个起始位、8 个数据位、1 个停止位的简化 UART 串行模型；
- TX FIFO（`pclk` 到 `uart_clk`）和 RX FIFO（`uart_clk` 到 `pclk`）；
- loopback、RX 数据可用中断、FIFO 空满状态和帧错误状态；
- 波特率 tick 生成，以及 APB 配置到 UART 时钟域的控制路径。

### 4.2 验证平台范围

验证平台应完成：

- APB 主机侧激励和事务监测；
- UART 外部输入激励，以及不依赖 DUT `bit_tick` 的 TX/RX 串行帧监测；
- 由 predictor 建立期望结果，由 scoreboard 只负责 TX、RX 数据比较；
- 对寄存器访问、错误路径、FIFO 边界、串行收发、复位和 CDC 压力的定向与约束随机测试；
- 对 APB 协议、错误响应、FIFO 使用边界和关键状态的 SVA 检查；
- 功能覆盖率、代码覆盖率、断言覆盖率的收集、合并和分析；
- 可重复执行的回归、日志和结果摘要。

## 5. 不在本阶段范围内的内容

以下内容不作为本项目的硬性交付，除非后续根据导师意见调整题目方向：

- 16 倍过采样、半位起始位确认、parity、可配置停止位和 break 检测；
- 面向真实晶振频率的标准波特率误差分析；
- AXI、AHB 等其他总线接口；
- 面向量产的低功耗、DFT、后端实现和完整 PPA 优化；
- FPGA 板级串口联调。

这些内容可以作为扩展或答辩加分项，但不应挤占验证闭环的时间。如果项目后续改成“UART IP 设计”方向，则需要重新纳入其中一部分，并补充综合、时序或 FPGA 证据。

## 6. 验收要求与对应证据

| 编号 | 验收内容 | 预期证据 |
| --- | --- | --- |
| RQ-01 | CTRL、BAUD 的复位值、读写和非法访问行为正确 | 普通寄存器测试、RAL 前门访问与 reset mirror、APB 断言 |
| RQ-02 | APB 写 TXDATA 后，数据能按顺序从 TX 串行输出 | TX monitor、scoreboard、loopback 测试 |
| RQ-03 | 外部 UART RX 和 loopback 数据能按顺序从 RXDATA 读回 | 外部 RX/loopback 测试、scoreboard |
| RQ-04 | TX/RX FIFO 的满、空、溢出、下溢和恢复行为明确且可验证 | 边界测试、状态检查、SVA |
| RQ-05 | IRQ、frame error 和 STATUS 位的置位、清除和异常行为可验证 | 新增 IRQ/frame-error 测试、断言、覆盖率 |
| RQ-06 | BAUD=0、常用分频值和运行中修改配置时的行为可解释 | 独立时序检查、波形和测试结果 |
| RQ-07 | 不同时钟比例、随机相位和独立复位下，数据通路与 FIFO 行为稳定 | CDC 压力回归、静态 CDC/lint 报告或替代说明 |
| RQ-08 | UVM 环境能够将数据遗漏、顺序错误和错误响应判为失败 | 强化后的 scoreboard、负向故障注入结果 |
| RQ-09 | 验证范围有量化结论 | 合并后的 functional/code/assertion coverage 报告及 waiver 说明 |
| RQ-10 | 最终结果可复现 | 带 commit SHA、工具版本、命令、seed 列表和结果的最终回归报告 |

## 7. 最终验收口径

正式提交前，至少应满足以下条件：

- 每项 RQ 都能对应到测试、SVA 或 scoreboard，并在追溯表中写明；
- 所有正式回归用例没有 `UVM_ERROR` 和 `UVM_FATAL`；
- 约束随机场景采用多 seed 回归，失败时能用 seed 和命令复现；
- 功能覆盖率达到计划覆盖点的 100%，不能达到的部分有明确 waiver；
- 输出 DUT 范围内的代码覆盖率和断言覆盖率，不只给出“有 covergroup”的描述；
- 对至少一个真实发现的问题保留完整记录：失败现象、日志或波形、根因、修改、回归结果和覆盖率变化；
- 最终报告记录源码提交版本、仿真器/UVM 版本、运行命令、seed、测试结果和覆盖率摘要。

代码覆盖率的具体数值不先写死。先完成第一次合并报告，再根据不可达代码和导师要求确定目标；重点是解释清楚覆盖范围和未覆盖原因，而不是为了一个百分比删改测试。

## 8. 后续工作顺序

1. 以本文档为基础，补一份需求—测试—断言—覆盖率的追溯矩阵；
2. 优先补 IRQ、frame error、RX FIFO 满、复位中传输、BAUD 时序和 CDC 压力测试；
3. 修正 scoreboard 与 SVA 中可能出现“测试通过但检查不完整”的情况；
4. 增加 UCDB 合并和覆盖率报告脚本，按未覆盖项补测；
5. 在最终提交版本上执行多 seed 回归，冻结报告、关键波形和一例 bug 闭环材料；
6. 再整理为论文图表、答辩 PPT 和演示脚本。

本说明是当前阶段的工作边界。后续若增加 parity、过采样或 FPGA 演示，应作为明确的扩展项记录，不和本阶段的基本验收混在一起。
